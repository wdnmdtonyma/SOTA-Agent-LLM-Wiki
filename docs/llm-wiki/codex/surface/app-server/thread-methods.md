> thread 方法是 app-server v2 管理 Codex thread 生命周期、订阅、目标、设置、历史读取和 thread-local 操作的 client request catalog。

## 能回答的问题

- thread/memory client request 当前有哪些 wire method？
- 哪些 thread 方法是 experimental 或按 params 字段检查 experimental gate？
- thread lifecycle、goal、metadata、background terminals、history/read/items 方法分别用哪些 params/response 类型？
- `memory/reset` 为什么归到 thread catalog？

## 字段模型

`ThreadStartParams` 定义在 v2 thread 模块，`ThreadStartResponse` 同模块返回 thread runtime 侧信息；`ThreadResumeParams`、`ThreadListParams`、`ThreadReadParams` 和 turns/items 分页 params 也都在 `thread.rs` 中维护。[E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:57][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:171][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:325][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1196][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1473][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1504][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1538]

`thread/increment_elicitation`、`thread/decrement_elicitation`、`thread/settings/update`、`thread/memoryMode/set`、background terminals、`thread/search`、`thread/searchOccurrences`、turns list 和 thread items list 在宏调用中带 experimental 标记或字段检查。[E: codex-rs/app-server-protocol/src/protocol/common.rs:517][E: codex-rs/app-server-protocol/src/protocol/common.rs:527][E: codex-rs/app-server-protocol/src/protocol/common.rs:566][E: codex-rs/app-server-protocol/src/protocol/common.rs:573][E: codex-rs/app-server-protocol/src/protocol/common.rs:605][E: codex-rs/app-server-protocol/src/protocol/common.rs:654][E: codex-rs/app-server-protocol/src/protocol/common.rs:660][E: codex-rs/app-server-protocol/src/protocol/common.rs:677][E: codex-rs/app-server-protocol/src/protocol/common.rs:684]

`thread/searchOccurrences` 在单个 thread 的可见 user message 与 final assistant message 中做 case-insensitive literal substring 搜索；分页结果给出 snippet、UTF-16 match range、turn/item ids 与可直接交给 `thread/turns/list` 的 inclusive turn cursor。该 request 明确 `serialization: None`，可并发读 persisted paginated history。[E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1376][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1404][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1409][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1411][E: codex-rs/app-server-protocol/src/protocol/common.rs:661][E: codex-rs/app-server-protocol/src/protocol/common.rs:664]

pinning 已从独立 `isPinned` patch/filter 迁移为通用 section 模型：`Thread` 返回 optional `section` 与 `sectionEnteredAt`，`thread/metadata/update` 不再接受 `isPinned`，`thread/list.sectionId` 是三态筛选——省略表示全部 section，`null` 表示未分组，字符串表示指定 section。[E: codex-rs/app-server-protocol/src/protocol/v2/thread_data.rs:174][E: codex-rs/app-server-protocol/src/protocol/v2/thread_data.rs:202][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:862][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1230]

`thread/section/move` 把 thread 移入、移出或在 section 内重排；`sectionId` 是 required-nullable，`beforeThreadId` 省略或为 null 时 append。`threadSection/list|create|update|delete` 管理独立持久化 section；这些操作依赖 SQLite state，缺少 SQLite 时返回 method-not-found，内置 Pinned section 不允许 rename/delete。[E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:918][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1123][E: codex-rs/app-server/src/request_processors/thread_sections.rs:104][E: codex-rs/app-server/src/request_processors/thread_sections.rs:141][E: codex-rs/app-server/src/request_processors/thread_sections.rs:163]

`ThreadSortKey` 新增 `section_position`，其默认方向是升序；`thread/search` 改用不含该值的独立 `ThreadSearchSortKey`，避免把 section rank 误用于全文搜索结果。[E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1263][E: codex-rs/app-server-protocol/src/protocol/v2/thread.rs:1310][E: codex-rs/app-server/src/request_processors/thread_processor.rs:2046][E: codex-rs/app-server/src/request_processors/thread_processor.rs:2052]

Paginated `thread/fork` 不再等同于复制一段内存 history：store 先冻结 source lineage，按 Latest/ThroughTurn/BeforeTurn 解析 durable boundary，并把 reference-backed history position 与 model context 交给 child。该 prepare path 使用进程内 lifecycle/read lease 与 writer mutex；跨进程 writer-lock conflict 属于 paginated create/resume，不应归因到 fork preparation。[E: codex-rs/thread-store/src/local/paginated_fork.rs:15][E: codex-rs/thread-store/src/local/paginated_fork.rs:23][E: codex-rs/thread-store/src/local/paginated_fork.rs:40][E: codex-rs/thread-store/src/local/paginated_fork.rs:73][E: codex-rs/thread-store/src/local/paginated_fork.rs:86][E: codex-rs/thread-store/src/local/paginated_fork.rs:160][I]
