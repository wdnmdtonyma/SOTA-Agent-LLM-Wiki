> V1 工具系统是当前活跑主线：`SessionPrompt.runLoop` 调 `SessionTools.resolve`，V1 registry 装配内建/插件/MCP 工具；普通模式将每个 MCP tool 以 AI SDK tool shape 交给 `streamText`，experimental code mode 则用单个 `execute` 工具承载经 permission 过滤的 MCP catalog。

## 能回答的问题

- V1 的内建工具、filesystem plugin tools、`plugin.list()` tools 和 MCP tools 分别从哪里进入模型可见工具集。
- `apply_patch` 为什么只在 GPT patch 条件下暴露，`edit/write` 为什么会被隐藏。
- V1 工具执行时 `ctx.ask`、plugin hooks、attachments、output truncation 和 AI SDK bridge 怎样串起来。
- `packages/llm` 在 V1 里为什么只是 `OPENCODE_EXPERIMENTAL_NATIVE_LLM` seam，而不是 V1 默认工具执行路径。
- `OPENCODE_EXPERIMENTAL_CODE_MODE` 怎样把多个 MCP tools 收敛成 wire id `execute`，又如何保留 permission 与 plugin hooks。
- 为什么 `packages/codemode/` 的 live wiring 留在 V1 权威节点，同时把 package runtime 与模型可见 surface 拆成独立节点。

## 1 职责与边界

### 职责

- 维护 V1 工具 registry service，提供 `ids()`, `all()`, `named()`, `tools(...)` 四个接口；`tools` 输入现在还带可选 session permission ruleset，用于 code-mode catalog 可见性。[E: packages/opencode/src/tool/registry.ts:77][E: packages/opencode/src/tool/registry.ts:78][E: packages/opencode/src/tool/registry.ts:79][E: packages/opencode/src/tool/registry.ts:80][E: packages/opencode/src/tool/registry.ts:81][E: packages/opencode/src/tool/registry.ts:85]
- 装配内建工具、filesystem-discovered plugin tools、runtime plugin tools，并按 provider/model 做 tool list 过滤；TaskTool 的 agent permissions 会改写 task tool 描述中的可用 agent 列表。[E: packages/opencode/src/tool/registry.ts:183][E: packages/opencode/src/tool/registry.ts:185][E: packages/opencode/src/tool/registry.ts:199][E: packages/opencode/src/tool/registry.ts:291][E: packages/opencode/src/tool/registry.ts:268]
- 把 V1 `Tool.Def` 转成 AI SDK `tool({ description, inputSchema, execute })`，并在 execute 前后触发 plugin hooks。[E: packages/opencode/src/session/tools.ts:99][E: packages/opencode/src/session/tools.ts:106][E: packages/opencode/src/session/tools.ts:121]
- 普通模式把 MCP native entries 转换后注入 AI SDK `tools` map，并对 MCP 文本输出做 V1 truncation；code mode 则在 direct MCP injection 之前返回。[E: packages/opencode/src/session/tools.ts:388][E: packages/opencode/src/session/tools.ts:390][E: packages/opencode/src/session/tools.ts:391][E: packages/opencode/src/session/tools.ts:464][E: packages/opencode/src/session/tools.ts:468][E: packages/opencode/src/session/tools.ts:474]
- 当 `OPENCODE_EXPERIMENTAL_CODE_MODE` 启用时，registry 动态 import `./code-mode`，把 wire id `execute` 放入 builtin list，且只有 permission-filtered MCP catalog 非空时才对模型暴露。[E: packages/opencode/src/effect/runtime-flags.ts:48][E: packages/opencode/src/tool/registry.ts:118][E: packages/opencode/src/tool/registry.ts:119][E: packages/opencode/src/tool/registry.ts:226][E: packages/opencode/src/tool/registry.ts:246][E: packages/opencode/src/tool/registry.ts:280][E: packages/opencode/src/tool/registry.ts:285][E: packages/opencode/src/tool/registry.ts:286][E: packages/opencode/src/tool/registry.ts:287][E: packages/opencode/src/tool/registry.ts:308]

### 非职责

- V1 registry 不负责 provider stream 本身；默认 stream 由 `LLM.stream` 内部的 AI SDK `streamText` 发起。[E: packages/opencode/src/session/llm.ts:280][E: packages/opencode/src/session/llm.ts:317]
- V1 registry 不负责 V2 durable settlement [I]；V1 AI SDK 甚至可能在 start-step event 前内部执行工具，processor 因此要预先捕获 snapshot。[E: packages/opencode/src/session/processor.ts:102]
- V1 registry 不是旧 `Bus` service。当前源码暴露的是 `GlobalBus` emitter，EventV2Bridge 把 EventV2 重新 emit 到 GlobalBus；`sync/README.md` 是关于早期 Bus/sync 设计的说明文档。[E: packages/opencode/src/bus/global.ts:22][E: packages/opencode/src/event-v2-bridge.ts:39][E: packages/opencode/src/event-v2-bridge.ts:46][E: packages/opencode/src/sync/README.md:39]

## 5 设计动机与 tradeoff

- V1 registry 同时承担 discovery、filter、prompt-shaping 和 execution bridge，是 AI SDK era 的高耦合中枢；这解释了为什么 tool-specific behavior 分散在 registry、session/tools 和每个 tool 文件中。[I]
- GPT patch gating 是 V1 的模型策略：`modelID.includes("gpt-") && !includes("oss") && !includes("gpt-4")` 时暴露 `apply_patch`，并隐藏 `edit/write`。[E: packages/opencode/src/tool/registry.ts:297][E: packages/opencode/src/tool/registry.ts:299][E: packages/opencode/src/tool/registry.ts:300]
- V1 plugin compatibility 优先：filesystem plugin tools 仍支持 Zod args 和 legacy JSON schema conversion，registry implementation normalizes missing args before building Zod/json schema。[E: packages/opencode/src/tool/registry.ts:130][E: packages/opencode/src/tool/registry.ts:133][E: packages/opencode/src/tool/registry.ts:134]
- `packages/codemode/` 提供通用 confined interpreter、schema-described tool tree 和 diagnostics，但当前 live wiring 是 V1 registry 的 experimental `execute` adapter [E: packages/codemode/src/codemode.ts:137][E: packages/codemode/src/codemode.ts:142][E: packages/codemode/src/codemode.ts:146][E: packages/codemode/src/codemode.ts:157][E: packages/opencode/src/tool/registry.ts:118][E: packages/opencode/src/tool/code-mode.ts:188]。本节点保留 live registry wiring；独立 package 运行语义由 `subsys.tools.codemode` 承载，模型可见的 wire surface 由 `tool.execute` 承载 [I]。
- V1 默认不是 native provider protocol runtime。`OPENCODE_EXPERIMENTAL_NATIVE_LLM` 打开时会尝试 native seam；不支持时明确 fallback 到 AI SDK。[E: packages/opencode/src/effect/runtime-flags.ts:54][E: packages/opencode/src/session/llm.ts:226][E: packages/opencode/src/session/llm.ts:260]
- 即使走 native seam，工具执行仍是 opencode-owned，并把 native tool call 适配回 AI SDK Tool.execute shape。[E: packages/opencode/src/session/llm/native-runtime.ts:175][E: packages/opencode/src/session/llm/native-runtime.ts:181]

## 6 Gotchas

- `packages/opencode/src/session/message-v2.ts` 名字里的 `v2` 不代表 V2 core tool runtime；V1 run loop 在这里调用的是 `MessageV2.toModelMessagesEffect` 做 V1 到 AI SDK/model message 的转换。[E: packages/opencode/src/session/prompt.ts:1262][I]
- V1 的 shell 工具文件名是 `shell.ts`，但 wire id 和 permission key 是 `bash`，这是 plugin/user/saved permissions 兼容要求。[E: packages/opencode/src/tool/shell/id.ts:16][E: packages/opencode/src/tool/shell/id.ts:17]
- V1 tools 可以来自 MCP，也可以来自 plugin；普通模式下 registry `ids()` 仍不包含后加的 direct MCP entries，code mode 下则包含代替它们的 registry tool `execute`。[E: packages/opencode/src/tool/registry.ts:261][E: packages/opencode/src/tool/registry.ts:262][E: packages/opencode/src/tool/registry.ts:246][E: packages/opencode/src/session/tools.ts:388][E: packages/opencode/src/session/tools.ts:390]
- `sync/README.md` 讲的是早期 Bus/sync 兼容设计；当前可检索代码里的 EventV2 listener/re-emit bridge 会把事件 emit 到 `GlobalBus`。[E: packages/opencode/src/sync/README.md:39][E: packages/opencode/src/event-v2-bridge.ts:39][E: packages/opencode/src/event-v2-bridge.ts:46]
