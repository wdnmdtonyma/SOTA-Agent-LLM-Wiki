> `ref.coding-agent.session-format` 是 pi-coding-agent 会话 JSONL 文件的字段级目录:第一行是 `SessionHeader`,后续每行是带 `id` / `parentId` / `timestamp` 的 append-only tree entry,当前产品格式版本是 v3。

## 能回答的问题

- pi-coding-agent session JSONL 文件第一行和后续行分别是什么 shape?
- JSONL v3 支持哪些 entry `type`,每种 entry 的字段、含义和写入入口是什么?
- v1/v2 legacy session 会怎样迁移到当前 v3?
- `compaction`、`branch_summary`、`custom`、`custom_message`、`label`、`session_info` 这些非普通消息 entry 如何进入上下文或 UI?
- coding-agent 产品层 `SessionEntry`、`FileEntry`、leaf 内存状态和 JSONL 文件行之间有什么格式边界?

## 文件外壳

session 文件是 JSON Lines:每一行都是带 `type` 字段的 JSON object;entry 通过 `id` / `parentId` 形成 tree,因此同一个文件能保留 branch 而不改写历史。[E: packages/coding-agent/docs/session-format.md:3] 默认文档位置写作 `~/.pi/agent/sessions/--<path>--/<timestamp>_<uuid>.jsonl`,其中 `<path>` 是 working directory 将 `/` 替换成 `-` 后的目录片段。[E: packages/coding-agent/docs/session-format.md:7][E: packages/coding-agent/docs/session-format.md:11] `SessionManager` 的默认目录编码实现会先 resolve cwd,再生成 `--...--`,并把文件放在 agent dir 的 `sessions/<encoded-cwd>/` 下。[E: packages/coding-agent/src/core/session-manager.ts:476][E: packages/coding-agent/src/core/session-manager.ts:477][E: packages/coding-agent/src/core/session-manager.ts:479][E: packages/coding-agent/src/core/session-manager.ts:480]

当前产品格式版本常量是 `CURRENT_SESSION_VERSION = 3`。[E: packages/coding-agent/src/core/session-manager.ts:30] `SessionHeader` 的字段是 `type: "session"`、可选 `version?: number`、`id`、`timestamp`、`cwd` 和可选 `parentSession`;`version` 可选是为了读取没有 version 的 v1 session。[E: packages/coding-agent/src/core/session-manager.ts:32][E: packages/coding-agent/src/core/session-manager.ts:33][E: packages/coding-agent/src/core/session-manager.ts:34][E: packages/coding-agent/src/core/session-manager.ts:35][E: packages/coding-agent/src/core/session-manager.ts:36][E: packages/coding-agent/src/core/session-manager.ts:37][E: packages/coding-agent/src/core/session-manager.ts:38] 新 session header 会写入当前 version、session id、ISO timestamp、`SessionManager` 持有的 cwd 和可选 parent session path;构造函数会把传入 cwd 解析后保存到 `this.cwd`。[E: packages/coding-agent/src/core/session-manager.ts:876][E: packages/coding-agent/src/core/session-manager.ts:934][E: packages/coding-agent/src/core/session-manager.ts:935][E: packages/coding-agent/src/core/session-manager.ts:936][E: packages/coding-agent/src/core/session-manager.ts:938][E: packages/coding-agent/src/core/session-manager.ts:939][E: packages/coding-agent/src/core/session-manager.ts:940][E: packages/coding-agent/src/core/session-manager.ts:941][E: packages/coding-agent/src/core/session-manager.ts:942]

## 版本与兼容

文档声明 v1 是 legacy linear entry sequence,v2 增加 `id` / `parentId` tree linking,v3 把 `hookMessage` role 改名为 `custom`;既有 session load 时会自动迁移到 v3。[E: packages/coding-agent/docs/session-format.md:21][E: packages/coding-agent/docs/session-format.md:23][E: packages/coding-agent/docs/session-format.md:24][E: packages/coding-agent/docs/session-format.md:25][E: packages/coding-agent/docs/session-format.md:27]

`migrateToCurrentVersion(entries)` 用 header version 或默认 `1` 判定迁移起点;小于 2 跑 v1->v2,小于 3 跑 v2->v3。[E: packages/coding-agent/src/core/session-manager.ts:281][E: packages/coding-agent/src/core/session-manager.ts:282][E: packages/coding-agent/src/core/session-manager.ts:283][E: packages/coding-agent/src/core/session-manager.ts:285][E: packages/coding-agent/src/core/session-manager.ts:287][E: packages/coding-agent/src/core/session-manager.ts:288] v1->v2 会给每个 non-header entry 生成 id、把 `parentId` 串到前一个 entry id,并把 legacy `firstKeptEntryIndex` 转成 `firstKeptEntryId` 后删除旧字段。[E: packages/coding-agent/src/core/session-manager.ts:231][E: packages/coding-agent/src/core/session-manager.ts:241][E: packages/coding-agent/src/core/session-manager.ts:242][E: packages/coding-agent/src/core/session-manager.ts:246][E: packages/coding-agent/src/core/session-manager.ts:248][E: packages/coding-agent/src/core/session-manager.ts:251][E: packages/coding-agent/src/core/session-manager.ts:253] v2->v3 会把 message role `hookMessage` 改写为 `custom`。[E: packages/coding-agent/src/core/session-manager.ts:260][E: packages/coding-agent/src/core/session-manager.ts:268][E: packages/coding-agent/src/core/session-manager.ts:270][E: packages/coding-agent/src/core/session-manager.ts:271]

## 读写边界

`SessionManager` 维护 `fileEntries`、`byId`、`labelsById`、`labelTimestampsById` 和 `leafId`;这些内存索引来自 JSONL 文件,但不是单独的 JSONL 行格式字段。[E: packages/coding-agent/src/core/session-manager.ts:862][E: packages/coding-agent/src/core/session-manager.ts:863][E: packages/coding-agent/src/core/session-manager.ts:864][E: packages/coding-agent/src/core/session-manager.ts:865][E: packages/coding-agent/src/core/session-manager.ts:866][I] `_appendEntry(entry)` 把 entry push 到 `fileEntries`,写入 `byId`,把 `leafId` 推进到该 entry id,再调用 `_persist(entry)`。[E: packages/coding-agent/src/core/session-manager.ts:1044][E: packages/coding-agent/src/core/session-manager.ts:1045][E: packages/coding-agent/src/core/session-manager.ts:1046][E: packages/coding-agent/src/core/session-manager.ts:1047][E: packages/coding-agent/src/core/session-manager.ts:1048]

持久化不是每个新 session header 都立即写盘: `_persist()` 在还没有 assistant message 且文件没有 flush 时会保持未 flush,等首次 assistant message 后用 `"wx"` 创建完整文件;已经 flush 的 session 后续使用 append。[E: packages/coding-agent/src/core/session-manager.ts:1018][E: packages/coding-agent/src/core/session-manager.ts:1019][E: packages/coding-agent/src/core/session-manager.ts:1020][E: packages/coding-agent/src/core/session-manager.ts:1029][E: packages/coding-agent/src/core/session-manager.ts:1030][E: packages/coding-agent/src/core/session-manager.ts:1032][E: packages/coding-agent/src/core/session-manager.ts:1040] 这说明 `getSessionFile()` 返回路径不等同于该路径已经存在于磁盘。[E: packages/coding-agent/src/core/session-manager.ts:1011][E: packages/coding-agent/src/core/session-manager.ts:1012][I]

## agent-core JSONL storage 边界

本节点在 `docs/llm-wiki/pi/index.json` 中的 source 只包括 `packages/coding-agent/src/core/session-manager.ts` 和 `packages/coding-agent/docs/session-format.md`;因此 agent-core `SessionTreeEntry` / `JsonlSessionStorage` 的具体字段差异不能在本 batch 内保留为 `[E]`,已降级到 staging 待对应 agent-core 节点或 index source 扩展后复核。[U]

coding-agent 产品层可核的边界是:JSONL 文件类型为 `FileEntry = SessionHeader | SessionEntry`,而当前 leaf 由 `SessionManager.leafId` 内存字段保存;`branch()` / `resetLeaf()` 只移动该字段,后续 append 用当前 `leafId` 作为 `parentId`。[E: packages/coding-agent/src/core/session-manager.ts:156][E: packages/coding-agent/src/core/session-manager.ts:866][E: packages/coding-agent/src/core/session-manager.ts:1360][E: packages/coding-agent/src/core/session-manager.ts:1364][E: packages/coding-agent/src/core/session-manager.ts:1372][E: packages/coding-agent/src/core/session-manager.ts:1373][E: packages/coding-agent/src/core/session-manager.ts:1061][I]
