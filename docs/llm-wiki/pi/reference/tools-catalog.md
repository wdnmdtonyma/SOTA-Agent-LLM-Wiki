> `ref.tools-catalog` 是 pi coding-agent 内置工具集的逐实例目录:以 `packages/coding-agent/src/core/tools/index.ts` 为 ground truth,列出 wire name、definition factory、preset、输入、输出 details、装配路径和源文件。

## 能回答的问题

- pi 内置工具的完整 wire name 清单是什么?
- `createCodingToolDefinitions`、`createReadOnlyToolDefinitions`、`createAllToolDefinitions` 分别包含哪些工具?
- 每个内置工具的 TypeBox 输入 schema 和 result `details` 大致是什么?
- built-in `ToolDefinition` 如何进入 `AgentSession` runtime?
- 内置工具有没有单独设置 `executionMode`?
- `read` / `bash` / `powershell` / `edit` / `write` 的默认 `constrainedSampling` 是什么，还要不要 `PI_EXPERIMENTAL`?
- `defaultTools` 如何选择初始 built-in set,会不会丢掉 extension/SDK custom tools?

## Ground Truth

`ToolName` 的字面量 union 是 `"read" | "bash" | "powershell" | "edit" | "write" | "grep" | "find" | "ls"` [E: packages/coding-agent/src/core/tools/index.ts:95]。`allToolNames` 是同一组八个 wire name 的 `Set<ToolName>`,从 `"read"` 列到 `"ls"`,第三项是 `"powershell"` [E: packages/coding-agent/src/core/tools/index.ts:96] [E: packages/coding-agent/src/core/tools/index.ts:99]。`createCodingToolDefinitions` 只返回 `read`、`bash`、`edit`、`write` 的 definition,不含 `powershell` [E: packages/coding-agent/src/core/tools/index.ts:164] [E: packages/coding-agent/src/core/tools/index.ts:166] [E: packages/coding-agent/src/core/tools/index.ts:167] [E: packages/coding-agent/src/core/tools/index.ts:168] [E: packages/coding-agent/src/core/tools/index.ts:169]。`createReadOnlyToolDefinitions` 只返回 `read`、`grep`、`find`、`ls` 的 definition,不含 `powershell` [E: packages/coding-agent/src/core/tools/index.ts:173] [E: packages/coding-agent/src/core/tools/index.ts:175] [E: packages/coding-agent/src/core/tools/index.ts:176] [E: packages/coding-agent/src/core/tools/index.ts:177] [E: packages/coding-agent/src/core/tools/index.ts:178]。`createAllToolDefinitions` 返回以 `ToolName` 为 key 的 record,逐一装入全部八个 definition,其中包括 `powershell: createPowerShellToolDefinition(...)` [E: packages/coding-agent/src/core/tools/index.ts:182] [E: packages/coding-agent/src/core/tools/index.ts:184] [E: packages/coding-agent/src/core/tools/index.ts:185] [E: packages/coding-agent/src/core/tools/index.ts:186] [E: packages/coding-agent/src/core/tools/index.ts:187] [E: packages/coding-agent/src/core/tools/index.ts:188] [E: packages/coding-agent/src/core/tools/index.ts:189] [E: packages/coding-agent/src/core/tools/index.ts:190] [E: packages/coding-agent/src/core/tools/index.ts:191]。


内置 `read`、`bash`、`powershell`、`edit`、`write` 的 definition 默认带 `constrainedSampling: { type: "json_schema", strict: "prefer" }`。`read` / `edit` / `write` 写在各自 factory 上 [E: packages/coding-agent/src/core/tools/read.ts:77] [E: packages/coding-agent/src/core/tools/edit.ts:156] [E: packages/coding-agent/src/core/tools/write.ts:57]；`bash` 与 `powershell` 都走 `createShellToolDefinition`，该 factory 设置同一字段 [E: packages/coding-agent/src/core/tools/bash.ts:238] [E: packages/coding-agent/src/core/tools/powershell.ts:53]。`grep` / `find` / `ls` 不设该字段。`wrapToolDefinition` 原样复制 `constrainedSampling` [E: packages/coding-agent/src/core/tools/tool-definition-wrapper.ts:14]。这不再要求 `PI_EXPERIMENTAL`：`experimental.ts` 只剩 `areExperimentalFeaturesEnabled()`（`PI_EXPERIMENTAL === "1"`），没有 `getExperimentalToolSampling()` [E: packages/coding-agent/src/core/experimental.ts:1] [E: packages/coding-agent/src/core/experimental.ts:2]。测试 `builtin-tool-strict-mode.test.ts` 断言五个 strict 工具在 `PI_EXPERIMENTAL` 为 unset / `"0"` / `"1"` 时都带该默认，且 `grep`/`find`/`ls` 为 undefined；扩展可把 `constrainedSampling: false` 传给 `wrapToolDefinition` [E: packages/coding-agent/test/builtin-tool-strict-mode.test.ts:13] [E: packages/coding-agent/test/builtin-tool-strict-mode.test.ts:18] [E: packages/coding-agent/test/builtin-tool-strict-mode.test.ts:23] [E: packages/coding-agent/test/builtin-tool-strict-mode.test.ts:27] [E: packages/coding-agent/test/builtin-tool-strict-mode.test.ts:38]。

同一 registry 现在也暴露直接返回 core `AgentTool` 的 `createTool` [E: packages/coding-agent/src/core/tools/index.ts:141]、`createCodingTools` [E: packages/coding-agent/src/core/tools/index.ts:195]、`createReadOnlyTools` [E: packages/coding-agent/src/core/tools/index.ts:204] 与 `createAllTools` [E: packages/coding-agent/src/core/tools/index.ts:213]；其成员集合分别与对应 definition preset 相同 [E: packages/coding-agent/src/core/tools/index.ts:196] [E: packages/coding-agent/src/core/tools/index.ts:205] [E: packages/coding-agent/src/core/tools/index.ts:214]。这组 API 省去 coding-agent extension `ToolDefinition` 适配层，适合直接嵌入 core agent。

`ToolDefinition.executionMode` 是可选字段 [E: packages/coding-agent/src/core/extensions/types.ts:479]。`wrapToolDefinition` 会把 definition 的 `executionMode` 原样转给 core `AgentTool` [E: packages/coding-agent/src/core/tools/tool-definition-wrapper.ts:16]。core `AgentTool.executionMode` 也是可选字段 [E: packages/agent/src/types.ts:411],`Agent` 构造时默认 `toolExecution` 为 `"parallel"` [E: packages/agent/src/agent.ts:237]。因此本目录把内置工具的 `executionMode` 记为 `unset -> default parallel`,因为八个 `createXToolDefinition` 返回对象都未声明 `executionMode`;`powershell` 走 `createShellToolDefinition`,该 factory 的返回对象同样没有 `executionMode` property [E: packages/coding-agent/src/core/tools/bash.ts:222] [E: packages/coding-agent/src/core/tools/bash.ts:231] [E: packages/coding-agent/src/core/tools/powershell.ts:53] [I]。
