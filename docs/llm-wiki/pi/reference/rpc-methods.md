> `ref.coding-agent.rpc-methods` 是 pi coding-agent RPC stdin command catalog:以 `RpcCommand` union 中互不相同的 `type:` 字面量为方法全集(**33**),并用 `rpc-mode.ts` 的 `switch (command.type)` 与 `docs/rpc-commands.md` 核对输入字段、成功 response 和运行时行为。

## 能回答的问题

- pi RPC mode 当前支持哪些 stdin command,一共几个?
- 每个 RPC command 的输入字段、可选字段和成功 response payload 是什么?
- `prompt`、`steer`、`follow_up` 三种发送消息入口有什么差异?
- session/model/thinking/queue/compaction/retry/bash 相关 command 分别调用哪个 runtime 方法?
- `get_commands` 返回的是内置 slash command 还是 extension/prompt/skill command?
- `extension_ui_response` 是否计入这 33 个 `RpcCommand`?

## Catalog 口径

`RpcCommand` 是 stdin command 的源码 ground truth。本页计数 = union 里互不相同的 `type: "..."` 字面量,当前 **33** 个:`prompt`、`steer`、`follow_up`、`abort`、`clear_queue`、`new_session`、`get_state`、`set_model`、`cycle_model`、`get_available_models`、`set_thinking_level`、`cycle_thinking_level`、`get_available_thinking_levels`、`set_steering_mode`、`set_follow_up_mode`、`compact`、`set_auto_compaction`、`set_auto_retry`、`abort_retry`、`bash`、`abort_bash`、`get_session_stats`、`export_html`、`switch_session`、`fork`、`clone`、`get_fork_messages`、`get_entries`、`get_tree`、`get_last_assistant_text`、`set_session_name`、`get_messages`、`get_commands` [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:20] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:22] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:74]。`RpcCommandType` 是 `RpcCommand["type"]` [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:303]。

`runRpcMode()` 的 `handleCommand()` 用 `switch (command.type)` dispatch 这些 command,未知 `type` 返回 `Unknown command` failure response [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:386] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:389] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:713] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:715]。

所有 command 都可带 `id?: string`;用户文档说明 response 会回显同一个 `id` 以便 correlation [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:22] [E: packages/coding-agent/docs/rpc.md:37]。成功 response 使用 `type: "response"`、`command`、`success: true`,失败 response 用任意 `command: string` 加 `success: false` 和 `error` [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:116] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:245]。`success()` helper 在 data 为 `undefined` 时省略 `data`,否则写入 `data` 字段 [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:64] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:69] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:72]。

`extension_ui_response` 是单独的 extension UI stdin sub-protocol,不是 `RpcCommand` union member;`handleInputLine()` 在普通 command cast 之前拦截 `type === "extension_ui_response"` 并 resolve pending UI request [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:294] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:750] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:771] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:773] [I]。`RpcExtensionUIRequest` 的 stdout methods 覆盖 `select`、`confirm`、`input`、`editor`、`notify`、`setStatus`、`setWidget`、`setTitle` 和 `set_editor_text`;这些是 UI request method,不计入本节点 33 个 command 实例 [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:252] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:253] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:287] [I]。

`prompt` 带 optional `streamingBehavior: "steer" | "followUp"`;成功 `prompt`/`steer`/`follow_up` 的 `data` 带 `disposition` [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:22] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:118] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:119] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:125]。`PromptDisposition` 是 `"handled" | "queued" | "started"`,`QueuedInputDisposition` 是 `"handled" | "queued"` [E: packages/coding-agent/src/core/agent-session.ts:294] [E: packages/coding-agent/src/core/agent-session.ts:295]。

命令字段的用户协议说明在 `docs/rpc-commands.md`;`docs/rpc.md` 只保留 mode/framing/lifecycle,并把 command details 指到 `rpc-commands.md` [E: packages/coding-agent/docs/rpc.md:33] [E: packages/coding-agent/docs/rpc.md:182]。
