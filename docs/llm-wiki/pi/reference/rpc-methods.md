> `ref.coding-agent.rpc-methods` 是 pi coding-agent RPC stdin command catalog:以 `RpcCommand` union 为方法全集,并用 `rpc-mode.ts` 的 switch dispatch 和 `docs/rpc.md` 的用户协议说明逐命令核对输入字段、成功 response 和运行时行为。

## 能回答的问题

- pi RPC mode 当前支持哪些 stdin command?
- 每个 RPC command 的输入字段、可选字段和成功 response payload 是什么?
- `prompt`、`steer`、`follow_up` 三种发送消息入口有什么差异?
- session/model/thinking/queue/compaction/retry/bash 相关 command 分别调用哪个 runtime 方法?
- `get_commands` 返回的是内置 slash command 还是 extension/prompt/skill command?
- `extension_ui_response` 和 extension UI request 是否计入 `RpcCommand` 方法目录?

## Catalog 口径

`RpcCommand` 是 stdin command 的源码 ground truth,当前 union 逐行列出 32 个 `type` 实例,从 `prompt` 到 `get_commands` [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:20] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:22] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:73]。`runRpcMode()` 的 `handleCommand()` 用 `switch (command.type)` dispatch 这些 command,未知 `type` 会返回 `Unknown command` failure response [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:385] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:388] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:710] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:712]。

所有 command 都可带 `id?: string`,用户文档说明 response 会回显同一个 `id` 以便 correlation [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:22] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:73] [E: packages/coding-agent/docs/rpc.md:26]。成功 response 使用 `type: "response"`、`command`、`success: true`,失败 response 用任意 `command: string` 加 `success: false` 和 `error` [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:115] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:231]。`success()` helper 在 data 为 `undefined` 时省略 `data`,否则写入 `data` 字段 [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:63] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:68] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:71]。

`extension_ui_response` 是单独的 extension UI stdin sub-protocol,不是 `RpcCommand` union member;`handleInputLine()` 在普通 command cast 之前拦截 `type === "extension_ui_response"` 并 resolve pending UI request [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:280] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:747] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:768] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:770] [I]。`RpcExtensionUIRequest` 的 stdout methods 覆盖 `select`、`confirm`、`input`、`editor`、`notify`、`setStatus`、`setWidget`、`setTitle` 和 `set_editor_text`;这些是 UI request method,不计入本节点 32 个 command 实例 [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:238] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:238] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:270] [I]。

## Response 与文档差异

`RpcResponse` 的 success variants 与 32 个 `RpcCommand` command 名一一对应,并额外有通用 failure variant;这说明 parse/unknown/validation/runtime failure 走同一 response envelope,而不是每个 command 单独定义 failure union [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:115] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:117] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:225] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:231] [I]。

`docs/rpc.md` 的 `get_commands` 示例和说明列出 `location`、`path` 等字段,但当前 `RpcSlashCommand` 类型和 `rpc-mode.ts` dispatch 实际输出 `sourceInfo` 对象字段,不是 top-level `location`/`path` 字段 [E: packages/coding-agent/docs/rpc.md:809] [E: packages/coding-agent/docs/rpc.md:824] [E: packages/coding-agent/docs/rpc.md:828] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:86] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:88] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:685] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:694] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:703] [U]。

`docs/rpc.md` 把 `get_messages` 放在 State 小节,但 `RpcCommand` union 用 Messages group 中的 command variant 暴露它,`handleCommand()` 也有单独 `get_messages` dispatch;这是文档组织和源码分组的差异,不是协议字段差异 [E: packages/coding-agent/docs/rpc.md:195] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:70] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:669] [I]。
