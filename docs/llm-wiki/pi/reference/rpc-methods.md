> `ref.coding-agent.rpc-methods` 是 pi coding-agent RPC stdin command catalog:以 `RpcCommand` union 为方法全集,并用 `rpc-mode.ts` 的 switch dispatch 和 `docs/rpc.md` 的用户协议说明逐命令核对输入字段、成功 response 和运行时行为。

## 能回答的问题

- pi RPC mode 当前支持哪些 stdin command?
- 每个 RPC command 的输入字段、可选字段和成功 response payload 是什么?
- `prompt`、`steer`、`follow_up` 三种发送消息入口有什么差异?
- session/model/thinking/queue/compaction/retry/bash 相关 command 分别调用哪个 runtime 方法?
- `get_commands` 返回的是内置 slash command 还是 extension/prompt/skill command?
- `extension_ui_response` 和 extension UI request 是否计入 `RpcCommand` 方法目录?

## Response 与文档差异

`RpcResponse` 的 success variants 与 33 个 `RpcCommand` command 名一一对应,并额外有通用 failure variant;这说明 parse/unknown/validation/runtime failure 走同一 response envelope,而不是每个 command 单独定义 failure union [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:116] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:118] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:125] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:233] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:239] [I]。

`docs/rpc.md` 的 `get_commands` 示例和说明列出 `location`、`path` 等字段,但当前 `RpcSlashCommand` 类型和 `rpc-mode.ts` dispatch 实际输出 `sourceInfo` 对象字段,不是 top-level `location`/`path` 字段 [E: packages/coding-agent/docs/rpc.md:832] [E: packages/coding-agent/docs/rpc.md:847] [E: packages/coding-agent/docs/rpc.md:851] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:87] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:89] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:690] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:699] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:708] [U]。

`docs/rpc.md` 把 `get_messages` 放在 State 小节,但 `RpcCommand` union 用 Messages group 中的 command variant 暴露它,`handleCommand()` 也有单独 `get_messages` dispatch;这是文档组织和源码分组的差异,不是协议字段差异 [E: packages/coding-agent/docs/rpc.md:218] [E: packages/coding-agent/src/modes/rpc/rpc-types.ts:71] [E: packages/coding-agent/src/modes/rpc/rpc-mode.ts:674] [I]。
