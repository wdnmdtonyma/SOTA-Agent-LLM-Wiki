> `ExtensionRunner` 是 pi-coding-agent 的扩展执行引擎: 它把 loader 产出的 extensions 和 shared runtime 绑定到当前会话, 构造 `ExtensionContext`, 并按事件类型顺序调用 extension handlers。

## 能回答的问题

- `bindCore()` 具体把哪些 session action 和 context action 绑定进 extension runtime?
- `ExtensionRunner.createContext()` 给 event handler 和 extension tool 暴露哪些运行时能力?
- 通用 `emit()` 和 `emitToolCall()`、`emitInput()` 等专用 emitter 的短路/聚合规则有什么不同?
- extension 注册的 tools、commands、shortcuts、flags、message renderers 如何在 runner 层汇总?
- project trust、provider registration、session-before cancellation 这些特殊路径怎样处理 error 和 result?
- reload/session replacement 后旧 extension context 为什么会变 stale?
- `ctx.ui.select/confirm/input/editor/custom` 怎样发出 `ui_prompt_start` / `ui_prompt_end`?
- `triggerTurn: false` 的 custom message 为什么要等 tool results 之后才插入 session?
- compaction 失败或 abort 时 `session_compact_failed` 谁 emit、带哪些字段?

## 设计动机与权衡

runner 把 loader 阶段的 declarative contributions 和 session 阶段的 live actions 分开: extension factory 可以先注册 handlers/tools/commands, 等 session 构建完再由 `bindCore()` 把真实 actions 填进 shared runtime [E: packages/coding-agent/src/core/extensions/runner.ts:327] [E: packages/coding-agent/src/core/extensions/runner.ts:357] [I]。这个设计让 extensionsResult 可以先被 resource loader 保存, 再由当前会话决定 UI mode、model registry、active tools 和 command context [I]。

专用 emitters 的存在是为了让不同事件拥有不同 combination policy: `tool_call` 支持 block 短路, `tool_result` 支持字段覆盖, `context` 和 provider payload 支持 chain transform, `input` 支持 handled/transform/continue 三态, `message_end` 有 role guard [E: packages/coding-agent/src/core/extensions/runner.ts:995] [E: packages/coding-agent/src/core/extensions/runner.ts:941] [E: packages/coding-agent/src/core/extensions/runner.ts:1047] [E: packages/coding-agent/src/core/extensions/runner.ts:1081] [E: packages/coding-agent/src/core/extensions/runner.ts:1267] [E: packages/coding-agent/src/core/extensions/runner.ts:900] [I]。

stale context guard 是 reload/session replacement 的安全边界: runner invalidated 后, context getters 和 command actions 都会通过 `assertActive()` 抛出 stale message, 而 command context 用 descriptor clone 保留 lazy getter, 避免提前读取旧值 [E: packages/coding-agent/src/core/extensions/runner.ts:593] [E: packages/coding-agent/src/core/extensions/runner.ts:602] [E: packages/coding-agent/src/core/extensions/runner.ts:807] [I]。
