> `AgentSession` 是 pi-coding-agent 的产品会话核心: 它把 `pi-agent-core` 的 `Agent`、会话持久化、extension runtime、工具注册、system prompt、compaction、retry、bash 和 tree navigation 组织成一个 run mode 可调用的 facade。同一 run 内，tool 执行与下一轮模型请求之间可通过 `prepareNextTurnWithContext` 插入 threshold compaction。

## 能回答的问题

- `AgentSession` 初始化时怎样把 `Agent`、`SessionManager`、`SettingsManager`、`ResourceLoader` 和 `ModelRegistry` 绑定起来?
- 一次 `prompt()` 进入 `agent.prompt()` 之前会经过哪些 extension、template、auth、compaction 和 message 构造步骤?
- RPC `steer` / `follow_up` 怎样经 `_queueUserInput` → `_runInputHandlers` → `emitInput` 进入队列?
- `getCompactionSettings(model)` 在哪些 compaction 路径上把 `modelOverrides` 交给 agent-core?
- `navigateTree()` 在 `isCompacting` 时为什么 throw,而不是 cancelled/排队?
- 同一 run 内 tool 执行之后、下一轮 assistant 请求之前，threshold auto-compaction 挂在哪个 hook 上?
- 截断的 compaction / branch summary 会不会落盘? provider 省略 streaming usage 时还会不会触发 threshold auto-compaction?
- `session_compact_failed` 在哪些失败/abort 路径发出?
- `sendCustomMessage({ triggerTurn: false })` 在 streaming / idle 时会不会 start 或 steer?
- agent-level retry 的 `retryDelayMs` 怎样被 `maxAgentDelayMs` 封顶?
