> `ExtensionAPI` 是 pi-coding-agent 给扩展 factory 的主入口:扩展以 TypeScript default factory 声明事件、工具、命令、快捷键、flag、renderer、provider,再由 loader 和 runner 把这些声明接到会话 runtime。

## 能回答的问题

- pi 扩展默认导出函数的形状是什么,同步和异步 factory 都支持吗?
- `ExtensionAPI` 上哪些方法是声明贡献点,哪些方法是运行期 action?
- `ExtensionContext`、`ExtensionCommandContext` 和 `ExtensionUIContext` 的边界是什么?
- 扩展在哪些位置被发现,加载期为什么部分 action 不能调用?
- `registerProvider()` 为什么加载期排队,绑定后立即生效?
- TUI、RPC、print、json 模式下扩展 API 有哪些可见差异?

## 1 Identity

扩展是可由 jiti 直接加载的 TypeScript 或 JavaScript module,default export 必须是 `ExtensionFactory`;loader 的 `isExtensionFile()` 接受 `.ts` 与 `.js`,并用 `jiti.import(extensionPath, { default: true })` 取 default export,非函数时返回 load error [E: packages/coding-agent/src/core/extensions/loader.ts:573] [E: packages/coding-agent/src/core/extensions/loader.ts:574] [E: packages/coding-agent/src/core/extensions/loader.ts:431] [E: packages/coding-agent/src/core/extensions/loader.ts:432] [E: packages/coding-agent/src/core/extensions/loader.ts:433] [E: packages/coding-agent/src/core/extensions/loader.ts:479]. `ExtensionFactory` 的类型是 `(pi: ExtensionAPI) => void | Promise<void>`,所以 factory 可以同步返回,也可以异步完成初始化 [E: packages/coding-agent/src/core/extensions/types.ts:1506].
